# HTML Report:用 HTML 页面交付"值得认真读"的内容

## 为什么

超过百行的 Markdown 几乎没人读完。当内容需要被认真理解(项目结构、方案取舍、复杂概念)时,一个有层次、有视觉编码、可交互的 HTML 页面才能真正被读进去。本技能的唯一目标:**美观、可读、可交互**。用户调用本技能就是明确表示愿意为质量多等一会儿——宁可多花时间打磨页面,不要退回纯文本。

## 工作流程

1. **先搞懂内容,再写页面。** 页面质量的上限是你对内容的理解深度。如果是项目总结:先探索代码库(目录结构、入口、核心模块、依赖关系、数据流),动手前列出页面要回答的 3~5 个核心问题——比如"这个项目是干什么的""代码从哪里开始读""模块之间怎么协作""改动通常发生在哪"。
2. **选择页面组织模式**(见下节),规划信息层级:第一屏给全局概览,细节折叠或分页,让读者自己决定钻多深。
3. **生成单文件 HTML**,遵守硬性要求和设计规范。
4. **交付**:保存文件,报告完整路径和 `file://` 链接;若环境支持(WSL 用 `wslview` 或 `explorer.exe`,macOS 用 `open`,Linux 桌面用 `xdg-open`),直接帮用户在浏览器打开。

## 硬性要求

- **完全自包含**:所有 CSS/JS 内联;禁止任何外部请求(CDN、字体、图片、分析脚本)。文件双击即可离线打开。这条限制的是文件的**运行时**而非生成时:确实需要图表库(如 ECharts)才能做好的页面,可以在生成时下载其压缩源码整体内联进 `<script>`;但手写 SVG 能解决的不要引库。
- **中文界面**:UI 文案用简体中文;代码、标识符、专有名词保持英文。
- **响应式**:宽内容(表格、代码块、图)放进 `overflow-x:auto` 容器;页面本身绝不横向滚动。
- **深浅色适配**:颜色全部定义为 CSS 变量,用 `@media (prefers-color-scheme: dark)` 切换,两种模式都要保证对比度。
- **保存位置**:默认存到当前项目根目录的 `ai-html-output/`(不存在则创建);用户指定了位置则听用户的。命名用 kebab-case 英文加日期,如 `payment-service-overview-2026-07-06.html`。同一主题多轮迭代改同一个文件,方便用户刷新浏览器看新版。

## 页面组织模式

按内容类型选骨架,可以混搭:

**项目总结 / 代码库理解(主场景)**
- 顶部:项目一句话定位 + 概览卡片行(技术栈、代码规模、入口文件、核心依赖)
- 架构图:内联 SVG 画模块关系,箭头标注数据/调用方向;悬停高亮相关模块
- 目录树:可折叠的 `<details>` 树,关键文件带一句话注释,非重点目录默认收起
- 模块卡片:每个核心模块一张卡(职责 / 关键文件 / 对外接口 / 依赖谁、被谁依赖)
- 阅读路线:给出"想理解 X 就按 1→2→3 顺序读这些文件"的导览
- 术语表:项目内部黑话、缩写、领域概念

**方案 / 技术选型对比**:方案并排卡片 + 维度对比表(✅/⚠️/❌ 编码),结论前置。

**概念讲解**:核心是可交互演示——滑块、按钮、可增删的节点,用户动一下立刻看到反馈;配对比表和术语表。

**评审 / 报告**:发现项按严重性颜色编码(红=阻塞、黄=建议、灰=备注),支持按严重性过滤;代码引用带文件路径和行号。

## 设计规范

美观不是装饰,是降低阅读负担。注意:模型天然向"平均值"收敛,产出一眼即知的"AI 味"页面——要主动对抗这个倾向。

**先定美学锚点,再写 CSS。** 动手前用一句话确定页面气质,比如"瑞士水疗馆般的极简高级""JetBrains 深色主题的工程感""纸质学术期刊的编辑感",之后所有视觉决策向锚点对齐。"好看一点"这类感觉词只会产出平均值,具体的锚点才产出质感。

**反 AI 味清单(禁止项):**
- 白底紫色渐变;均匀平铺的彩虹配色
- 千篇一律的"hero 区 + 三栏卡片"模板脸布局
- 纯白/纯灰的死板背景
- 界面装饰性图标用 emoji(内容中的状态标记 ✅/⚠️/❌ 除外)

**具体做法:**
- **排版**:中文正文用系统字体栈即可(苹方/微软雅黑质量本身很高),性格靠"对比"制造——标题与正文拉开字重(如 300 对 700)和字号差距,大标题可加轻微负字距;编辑感页面可改衬线栈(Georgia, 'Songti SC', serif)。正文 15~16px、行高 1.6~1.7;主列 680~900px 居中,大屏加粘性侧边目录。
- **颜色**:页面顶部先用 CSS 变量定义一套 token(1 个主色 + 5 档中性灰阶 + 语义色),全文只从 token 取色,保证第 10 个组件和第 1 个风格一致。一个克制的主色 + 锐利的强调色,优于多色平铺;配色可借鉴成熟 IDE 主题(Nord、Monokai、Solarized)。
- **背景**:给氛围而不是纯色——极淡的渐变叠层、细微的几何/噪点纹理(CSS 或内联 SVG 实现),让页面有深度。
- **质感词表**(用技术手段替代形容词):backdrop-blur、多层 soft shadow、半透明 1px subtle border、hover feedback、scroll reveal、micro-interactions。动效克制(120~250ms),只用于反馈与引导。
- **图标**:界面图标用内联 SVG(可直接复用 lucide/heroicons 的 path,MIT 协议,每个几行),观感远好于 emoji。
- **代码块**:内联 JS 做简单语法高亮(关键字/字符串/注释三色足够),每块带复制按钮。
- **页头元信息**:标题、生成日期、对应任务的一句话描述。
- 若环境中有 `frontend-design` 或 `dataviz` 技能,做视觉设计或画图表前先调用它们。

## 交互组件

按需使用,别为交互而交互:

- 标签页(tabs)切换视角;`<details>/<summary>` 折叠次要内容
- 表格排序、关键字过滤(内容超过 ~15 行才值得加)
- **回传闭环**:凡是用户可能在页面上调整的内容(选中的方案、调好的参数、编辑过的文本),放一个「📋 复制」按钮把当前状态序列化成文本,让用户一键粘回对话继续迭代
- 所有交互用原生 JS 实现,并且要能静默降级——即使 JS 不执行,页面内容也完整可读

## 交付前自检

- [ ] 文件中无任何 `http(s)://` 外部资源引用
- [ ] 深色和浅色模式都检查过对比度
- [ ] 窄窗口(~400px)下页面不横向滚动
- [ ] 页面有明确的美学锚点,没踩"反 AI 味清单"里的任何一条
- [ ] 向用户报告了完整文件路径
