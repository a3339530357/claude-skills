# HTML 报告的视觉与技术规范

本文件让技能**自带**出片能力,不依赖 `html-report` / `frontend-design` 等外部技能是否
存在。若运行时确实有这些技能,优先调用它们(它们更新更快);没有就按本文件做,产出
质量不应有明显差别。

---

## 一、风格连续性(先做这一步)

日报是**每天一份的连续系列**,不是一次性作品。同一系列里每天换一套视觉,读者需要
重新适应,历史对比也无从下手。所以动手前先看前一天的:

```bash
ls -1t <输出目录>/*.html 2>/dev/null | head -3
```

找到最近一份就读它的 `<style>` 块与骨架结构,继承这几样:

| 继承 | 具体指 |
|---|---|
| 配色 token | CSS 变量名与色值,深浅两套 |
| 字体角色 | display / body / mono 各用什么栈 |
| 版心与间距 | max-width、区块间距节奏 |
| signature 元素 | 上一版的标志性元素(时间轴样式、状态徽章形态等) |
| 骨架顺序 | 概览 → 时间线 → 问题卡 → 学到 → 遗留 → 采集说明 |

**可以变的**:内容结构随当天实际情况调整(某天没有提交就不要硬留提交区块);某个
组件确实不好用可以改进,但改进后要沿用下去。

**不要**每天重新发明配色和布局。第一份定调,后续是迭代。

若输出目录里没有历史文件(首次生成),按下文自行定调。

## 二、硬性要求

- **完全自包含**:CSS/JS 全部内联,禁止任何 `http(s)://` 外部请求(CDN、字体、图片、
  分析脚本)。文件双击即可离线打开。图表优先手写内联 SVG;确实需要图表库才能做好的,
  在生成时把压缩源码整体内联进 `<script>`。
- **中文界面**:UI 文案用简体中文;代码、标识符、异常类名、文件路径保持英文原样。
- **响应式**:宽内容(表格、代码块、堆栈)放进 `overflow-x:auto` 容器;页面本身
  绝不横向滚动。窄到 400px 也不能溢出。
- **深浅色适配**:颜色全部定义为 CSS 变量,`@media (prefers-color-scheme: dark)` 切换,
  两种模式都要过对比度。**`:root` 必须声明 `color-scheme`**(浅色 `light`、深色分支
  `dark`),否则深色模式下原生控件(复选框、滚动条)会突兀地留成白色。
- **无障碍**:交互元素要有可见的 `:focus-visible`;动效尊重
  `@media (prefers-reduced-motion: reduce)`。
- **宽屏**:版心限宽居中(1100~1400px),4K 下靠全宽骨架背景化解两侧留白,
  **不要**用放大字号或拉伸 SVG 去"铺满"。正文行宽限 60~75ch。

## 三、视觉设计

美观不是装饰,是降低阅读负担。模型天然向"平均值"收敛、产出一眼即知的"AI 味"页面,
要主动对抗。

**先定美学锚点,再写 CSS。** 用一句话确定页面气质,之后所有视觉决策向它对齐。
"好看一点"只会产出平均值,具体锚点才产出质感。日报这类内容适合的方向举例:
"核电控制室的仪表面板""JetBrains 深色主题的工程感""纸质工程记录本"。锚点应当来自
**当天内容的领域**——排障日报和前端重构日报不该长得一样。

**禁止项:**
- 白底紫色渐变;均匀平铺的彩虹配色
- "hero 区 + 三栏卡片"的模板脸布局
- 纯白/纯灰的死板背景
- 界面装饰用 emoji(内容里的状态标记 ✅/⚠️/❌ 除外)

**具体做法:**

- **排版**:中文正文用系统字体栈(苹方 / 微软雅黑质量本身很高)。性格靠**对比**
  制造——标题与正文拉开字重(300 对 700)和字号差距,大标题可加轻微负字距。
  正文 15~16px、行高 1.6~1.7。等宽字体用 `ui-monospace, Consolas, monospace`。
  编辑感页面可换衬线栈 `Georgia, 'Songti SC', serif`。**不要任何 web 字体或 @import。**
- **颜色**:顶部先定一套 token(1 个主色 + 5 档中性灰阶 + 语义色),全文只从 token
  取色,保证第 10 个组件和第 1 个风格一致。一个克制的主色 + 锐利的强调色优于多色平铺。
  配色可借鉴成熟 IDE 主题(Nord、Monokai、Solarized)。
- **背景**:给氛围而非纯色——极淡的渐变叠层、细微的几何/噪点纹理(CSS 或内联 SVG)。
- **质感**:用技术手段替代形容词——多层 soft shadow、半透明 1px border、hover 反馈、
  micro-interactions。动效克制(120~250ms),只用于反馈与引导。
- **图标**:内联 SVG(可复用 lucide/heroicons 的 path,MIT),观感远好于 emoji。
- **结构性装置要编码真实信息**。编号 01/02/03 只在内容真是序列时才用。日报里
  **时间是天然的序**,用它做主轴比编号更有信息量。

**把大胆用在一处。** 让 signature 元素成为唯一被记住的东西,周围保持安静克制。
Chanel 的建议:出门前照镜子,拿掉一件配饰。

## 四、日报专属的呈现要点

- **代码差异**:Java/配置的前后对照用 `+`/`-` 行标记,加背景色区分增删。不要只给
  改后的版本——留档的价值在于看出**改了什么**。
- **异常堆栈**:等宽字体,异常类型和业务帧用强调色标出,框架帧可淡化。
- **时间线**:提交是被"消解"的关键节点,视觉上应最重;学习类事件是支线,可淡化。
  事件间距可按真实时长缩放,疏密即节奏。
- **遗留项**:用 `<input type="checkbox">` 让用户勾选,状态存 `localStorage`
  (键名带日期),再配一个「复制未完成项」按钮把状态序列化成文本粘回对话。
- **未闭环的坑要显式标记**。"机制未明"这类徽章比埋在正文里有用得多。

## 五、交付前自检

用程序化自检,不要截图后读图(纯文本模型 Read PNG 会 API 400):

```bash
node <SKILL_DIR>/scripts/lint-html.js <html绝对路径> 400,1280,2560
```

报告里任何 `✗` 都是真问题。重点盯:各断点横向溢出、外部资源引用、
`color-scheme(dark)` 是否为 dark。

程序查不到、需要自己过一遍的:
- [ ] 有明确的美学锚点,没踩「禁止项」里的任何一条
- [ ] 与前一天的报告风格连续
- [ ] 代码差异能看出改了什么,不只是改后结果
- [ ] 向用户报告了完整文件路径
