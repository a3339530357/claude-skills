# session-handoff：会话交接

## 目的

长会话逼近上下文上限时，与其在降质的对话里硬撑，不如干净地交接：把当前会话压缩成一份**自包含**的交接文档，配一段可直接粘贴到新会话的开场提示，让新会话读一个文件就恢复全部工作状态。

与两个相近机制的区别（避免选错工具）：

- `/compact`：模型内部窗口压缩，产出对用户不可见、不可携带，且有摘要失真。本技能产出的是用户可见、可编辑、可跨会话复用的文档。
- `ccmd-archive`：面向"三个月后的自己"的长期备忘录，沉淀踩坑与决策。本技能面向"三天内的新会话"——时效短、颗粒度细到"下一步做什么"。

## 执行步骤

1. **回顾会话**：通读当前对话，按模板的六个部分识别要保留的信息
2. **定位项目根**：交接文档放在项目根的 `handoff/` 目录（不存在则创建）。项目根 = 会话主要讨论的那个含 `.git` / `package.json` 等标志的目录
3. **命名**：`handoff/YYYY-MM-DD-<会话主题>.md`，主题用中文短词（30 字内，避免空格，用 `-` 连接）；同名已存在则追加 `-2`、`-3`
4. **写交接文档**（模板见下）
5. **生成开场提示**（要求见下）
6. **简短反馈**：只报告文件路径 + 开场提示本身，不要把交接文档全文刷进对话

## 交接文档模板

```markdown
# <会话主题>

> 交接时间：YYYY-MM-DD HH:mm · 本文档为新会话准备，自包含，无需读旧 transcript

## 任务目标与背景

（本次会话在做什么、为什么）

## 关键结论与决策

（已确认的事实、做出的选择及理由。重点抢救"为什么"——做了什么可以从文件和
git 恢复，为什么这么做的依据只存在于对话里）

## 关键路径与产物

（文件路径、命令、外部资源。逐字保留，不得改写或简写路径）

## 进行中的工作

（当前进行到哪一步、下一步是什么——新会话的第一件事从这里开始）

## 用户偏好与约束

（会话中用户明确表达的工作习惯、禁止事项，如"不要自动 git commit"）

## 未解决问题与风险
```

## 开场提示生成要求

文档写完后，输出一段用户可直接粘贴到新会话的开场白：

```
请先读 <交接文档绝对路径> 恢复上下文。
当前进度：<一句话>
接下来：<下一步任务>
```

给绝对路径而非相对路径：新会话的 cwd 可能不同，相对路径会读不到。

## 约束

- **保真**：不得编造。数字、路径、命令逐字保留；推断内容标注"推断"
- **敏感信息**：API key、密码、token 一律不写入文档——只写"存放在 <位置>"（如 `platform/.env`）
- **克制**：信息量以"新会话能接续工作"为准，不是越多越好。写给三天后打开新会话的自己，避免"我们之前讨论的那个方案"这类悬空指代
- **交接后即冻结**：文档写完、开场提示给出后，本会话不再开始新任务——用户接下来该做的是开新会话，不是继续在这里聊。若用户坚持继续，提醒：后续内容不会进入已写好的交接文档，需要重新执行本技能
